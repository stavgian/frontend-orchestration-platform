How it works

A live demo of a micro-frontend platform. This page is the shell portal: it reads a manifest, loads {{ mfes.length }} independent apps built with different frameworks, owns one active context and lets the apps talk through a shared message channel. It contains no business logic. What the example means comes from a scenario file and from the apps themselves.

What happens, step by step

  1. 1. Discover The shell fetches the manifest, the only place that says which apps exist and where to load them from. Listed below under “Manifest”.
  2. 2. Load When you open a record, each compatible app is loaded on demand as a script and mounted as a web component. Each app is built and deployed on its own. “Built with” under each app shows the framework it reports at runtime.
  3. 3. Share context The record you open becomes the active context. The shell announces context:changed; an app that loads later asks with context:get. Apps never change the route. Switch records on a detail page: nothing reloads, every app updates itself.
  4. 4. Communicate Apps publish events, ask each other questions and announce when they join or leave, using @stavgian/mfe-communication, the only code they share. Open the Message log and trigger an action in any app.
