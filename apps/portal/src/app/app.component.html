How the apps talk

Example use case: a small shop. Add a product in the catalog and the cart, checkout and shipping each react, without any of them importing the others. Four ways the apps talk make that possible:

  1. Events “Something happened.” The sender does not know who is listening. Add a product: the cart, checkout and shipping all react.
  2. Direct messages “This is for you.” The same message, addressed to a single app. “Checkout →” in the cart reaches checkout only. The catalog never sees it.
  3. Requests “I need an answer.” One app asks, and the app that knows replies. On “Place order”, checkout asks the cart to confirm the total.
  4. Presence “Who is here?” Apps announce when they join and when they leave. Checkout waits for the cart, and “Check who’s online” asks everyone at once.

What you are looking at

A live demo of a micro-frontend platform. This page is the shell portal. It loads four independent apps, built with different frameworks, and lets them talk to each other. It is not a real shop; it exists to show the pattern.

What it shows: apps in different frameworks side by side, each deployed on its own, a manifest in place of hard-wired imports, and one small typed channel in place of shared code.

  1. Shell portal This page, built with Angular. It reads the manifest, loads each app on demand, draws the frame around them and watches the message channel. It has no business logic and no built-in knowledge of the apps. Everything inside the dashed frame belongs to the shell portal.
  2. Manifest A JSON file that lists the apps: their name, colour, logo and where to load each one from. Add an entry and a new app appears; the shell's code does not change. Open Manifest in the top bar to read the real file.
  3. The four apps Product catalog (Angular), shopping cart (React), checkout (plain JavaScript) and shipping (Vue). Each is built, versioned and deployed on its own, and appears as a web component. The inner dashed frame marks them as micro-frontends. “Built with” under each app shows the framework and version it reports at runtime.
  4. The npm library @stavgian/mfe-communication is the only code the apps share. It gives them events, direct messages, requests and presence over browser CustomEvents, with typed messages, in under 4 KB. Open the Message log, add a product and follow the messages.
